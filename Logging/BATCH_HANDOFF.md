## Deployment implementation

- `Data Ingestion/Batch/Databricks/MeridianBatch.scala` is generated by `Data Ingestion/Batch/Databricks/BuildNotebook.ps1` from the same Scala source and the four sample CSVs. Databricks compiles the notebook on the chosen runtime. This avoids loading a Scala 2.12 JAR on Scala 2.13 compute.
- The notebook creates a project schema with managed storage at meridian/managed when the schema is new, exposes meridian/source via an external volume, and can stage the sample CSVs. It writes Bronze, Silver, rejects, audit and Gold Delta outputs below meridian/batch, plus five native managed Iceberg tables. It compares Delta and Iceberg KPI contents after publishing.
- `Data Ingestion/Batch/Databricks/DeployBatch.ps1` imports the notebook and submits it as a one-time job on a running cluster. It takes a catalog name as a parameter. The deployed notebook is under /Shared/meridian-batch/MeridianBatch.
- The Unity Catalog catalog name and CREATE SCHEMA / CREATE MANAGED STORAGE / CREATE EXTERNAL VOLUME permissions still need discovery. Select a writable project catalog. If meridian schema already exists, confirm its managed location before relying on Iceberg storage to land under this project prefix.
