# Project Meridian Requirements and Evidence

The [capstone brief](PROJECT_MERIDIAN_Capstone_Logistics_Intelligence_Real-Time_Tracking.docx) describes 8,768 shipment records. Verification used the [trainer-supplied mini pack](../Datasets/README.md) of 141 shipment rows and 43 tracking records. The ADLS acceptance run added two synthetic events. The evidence covers functional behavior on the mini pack. Performance and correctness at full-dataset scale require a separate run.

## Verification scope

The matrix references archived results from separate executions. GitHub Actions rebuilds the workload images and runs the packaged batch check. Azure Databricks, Kubernetes operations, and ADLS recovery are verified separately. The [fresh local demonstration attempt](../Testing/evidence/meridian-final-demo-attempt.log) reached 141 input rows and 133 latest versions before Docker Desktop stopped responding. The batch job timed out before the ADLS replay stage. See the earlier [successful ADLS recovery log](../Logging/meridian-adls-recovery-verification.log) for that test's results.

The local Docker Compose path was also exercised on 2026-11-23: Kafka accepted one synthetic event, Spark classified it as `ACCEPTED` in Delta, wrote its replay record and committed one Iceberg event window. The event's micro-batch took about 90 seconds on this workstation. The configured two-second processing trigger is a scheduling interval, not a measured end-to-end latency target. After merge, GitHub Actions completed successfully on `main` commit `8ea5f356227f3925e4c6b878212a143fb66a7c30`: both jobs passed, including the Compose configuration check. CI validates the configuration and builds the Spark image; it does not run the Kafka-to-Spark live event demonstration or establish a latency target. See the [successful CI run](https://github.com/ShanmukhaAaryasree/project-meridian/actions/runs/45182186442).

## Execution environments

- **Local Docker Desktop and Kubernetes** ran the packaged batch job, Kafka fixture replay, PVC recovery, producer rollout and rollback, and failure diagnosis. The Delta upsert regression ran in an isolated Spark container.
- **Azure Databricks** ran the historical notebook and published the four KPI outputs. The plan uses a Unity Catalog volume for inputs and managed tables for outputs. The saved exports show KPI parity and the evolved Iceberg column.
- **Azure Data Lake Storage Gen2** held the streaming checkpoint, Iceberg tables, and Delta event audit for the cloud-storage acceptance test. Spark and Kafka still ran on local Kubernetes during that test.
- **GitHub-hosted Actions** passed both jobs on the merged `main` commit `8ea5f356227f3925e4c6b878212a143fb66a7c30`. The processing job built the batch and stream images, validated the real-time Compose configuration, and passed the batch reconciliation check. [Successful workflow run](https://github.com/ShanmukhaAaryasree/project-meridian/actions/runs/45182186442)
